# Stage 1：从"全量文本"到"操作"（Operation）

## 运行

```bash
node stage1/server.js   # 端口 8001，开两个浏览器标签页访问
```

## 本阶段实现

- **操作模型**：编辑动作表达为 `{kind:'insert', pos, str}` / `{kind:'delete', pos, len}`
- `diffToOps()`：比较输入前后文本，把变化翻译成操作（公共前缀/后缀 diff）
- `applyOp()`：前后端共用同一套操作应用逻辑
- 朴素光标修正：远端操作发生在光标前，光标跟着挪（transform 的思想萌芽）
- 教学工具：操作日志面板、文档校验值（哈希）、800ms 模拟网络延迟（稳定复现并发）

## 已知弊端

1. **位置漂移**：`pos` 是相对坐标。操作基于"我生成它时看到的文档"，送达对方时文档已变，坐标失效——并发下两边**静默发散**（校验值不同）
2. 服务端没有版本概念，**无法检测**冲突，更无法修正

## 后续阶段如何解决

- **Stage 2**：加版本号 + 服务端全局定序，冲突可检测、可强制收敛（但会丢编辑）
- **Stage 3**：`transform()` 修正过期操作的坐标，不再丢编辑（OT 核心）
- **Stage 4**：完整的客户端控制算法（缓冲、双侧变换）
