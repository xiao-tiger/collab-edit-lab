# O6 · History 不能无限增长，Undo 不能回退全文

一个长期运行的文档会产生两个工程问题：

1. `history` 越来越长，每次 transform 都要扫描更多操作；
2. 多人环境中直接恢复旧全文，会把其他人的后续修改一起删除。

## 逐步观察选择性 Undo

先演示 A 撤销自己的插入但保留 B 的“已审”，再切换到快照场景，观察太旧的操作为什么只能 resync。

## Undo 是一条新的操作

操作被服务端接受前，先根据当前文档计算 inverse：

```js
inverse(insert(pos, str))
  = delete(pos, str.length)

inverse(delete(pos, len))
  = insert(pos, 被删除的原文字)
```

真正撤销时，inverse 的坐标也可能已经过期，所以还要穿过目标操作之后的全部历史：

```js
let undoOp = target.inverse

for (const entry of history.slice(target.rev)) {
  undoOp = transform(undoOp, entry.op, false)
}

applyAsNewOperation(undoOp)
```

远端操作不进入用户的本地 Undo 栈；Undo/Redo 生成新的正常操作，继续获得 rev、进入 history 并广播。

## 快照截断

服务端定期保存：

```js
{
  doc,
  rev,
  snapshotRev: rev,
}
```

然后清理旧 history。代价是 `baseRev < snapshotRev` 的离线操作已经找不到完整变换路径，只能回退为权威快照 resync。

## 本章答案

生产形态不是无限保存所有历史：近期操作用 history 精确 transform，太旧操作用快照恢复。选择性 Undo 通过“逆操作 + 后续 transform”只撤销自己的意图。
