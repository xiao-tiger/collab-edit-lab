# C2 · 迷你 RGA（文本 CRDT）

抛弃「位置坐标」，给每个字符发一张全局唯一的身份证——合并退化为求并集，乱序/重复天然免疫。这是 CRDT 篇的核心（约 80 行）。

## 动手实验

<CrdtRgaSim>
① 两边同时打字 → 文本与内部结构都收敛 ② 勾捣乱开关 → 毫无影响 ③ A 删一段的同时 B 往里打字 → B 的字**存活**（对照 OT 的 delete 吸收）④ 观察删除线：墓碑从未离开结构

## 核心结构

```js
Item = {
  id: 'B:3',        // 站点id + 计数器：全局唯一、可比较
  left: 'A:5',      // 我插入时左边那个字符的 id（"我出生在谁右边"）
  ch: 'X',
  deleted: false,   // 删除 = 打墓碑，不物理移除（否则后来者无法引用它）
}
```

- **插入**：新字符的 `left` 指向目标位置左边的字符
- **合并**：按 id 求并集（墓碑「删过即删」）——三性质由并集天然保证
- **重建文本**：从根 DFS；同一 `left` 的并发兄弟按 id **降序**（"后来者居左"——否则在开头打字、字会跑到后面，我们的测试抓到过这个 bug）

## 与 OT 的对照

| | OT（Stage 3） | RGA（C2） |
|---|---|---|
| 定位 | 相对位置 pos | 绝对身份 id |
| 并发修正 | transform + 中心定序 | 不需要——不存在「过期」 |
| 版本号 | rev / baseRev 必需 | 不需要 |
| delete × 并发 insert | **吸收**（插入被删） | **插入存活** |
| 乱序/重复 | 需要定序保证 | 天然免疫 |
| 代价 | 需要中心服务器 | 墓碑膨胀、每字符元数据 |

## 小结

**✅ 学会了什么**：Item 身份证模型；合并=并集；兄弟降序排序的原因。

**⚠️ 还有什么问题**：墓碑只增不减；交替并发插入同一位置可能交错（Yjs 的 YATA 解决）；状态型发全量。
