# C2 · B 到底有没有看过 A 的修改

同样是两个标题版本，背后可能是两种完全不同的过程。

```text
情况一：A 改完并同步给 B，B 看过后再改
情况二：A、B 都断网，各自修改，谁也不知道对方
```

现实时间相差几秒不重要。CRDT 真正关心的是：**一个修改产生时，它已经观察过哪些历史？**

## 用版本向量记录“我见过什么”

两个副本 A、B 的版本向量可以写成：

```js
{ A: 1, B: 0 }
```

意思不是“版本号是 10”，而是：我见过 A 的 1 次修改，还没见过 B 的修改。每个副本本地修改时，只增加自己的分量；收到远端状态时，每个分量取 `max`。

## 四种比较结果

```text
before      A 的历史被 B 完整包含
after       B 的历史被 A 完整包含
equal       双方见过相同历史
concurrent  各自知道一部分，谁也没有包含谁
```

版本向量采用逐项比较，不是把 `[1, 0]` 当成数字 10，也不是从左到右比较大小。

```text
[1,0] 与 [1,1] → before
[1,0] 与 [0,1] → concurrent
```

## 本章答案

版本向量负责发现“因果先后”与“并发”。如果 B 的向量包含 A 的全部历史，B 就是因果上的后续；如果两个向量交叉，两次修改就是并发。
