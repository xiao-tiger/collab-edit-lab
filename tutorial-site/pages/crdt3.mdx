# C3 · 两个并发标题到底显示哪个

现在我们已经知道下面两个修改互相并发：

```text
A：周报 v2        vector=[1,0]
B：周报最终版     vector=[0,1]
```

并发只说明双方修改时互不知情，并不自动产生一个正确答案。产品必须选择冲突语义。

## 两种常见选择

**LWW Register**：通过可比较的 `stamp` 确定性地选择一个赢家。界面始终只有一个值，但会丢掉另一个并发版本。

**MV-Register**：保留所有并发值，显示“存在冲突”，等待用户产生一个同时观察过旧版本的新版本。

## 动手选择策略

先用 LWW，看 `(counter, actor)` 如何打破平局；再切换到 MV，看冲突怎样被保留和消除。

## stamp 和版本向量不是一回事

```text
版本向量：判断 before / after / concurrent
stamp：当产品选择 LWW 时，为并发版本稳定地选一个赢家
```

如果系统只需要 LWW，也可以只保存 Lamport stamp。但这样只能知道谁赢，无法区分“看过后修改”和“离线并发”。

## Doc 文档怎么选

- 普通标题、颜色、开关：通常使用 LWW；
- 不能静默丢失的重要结论：可以使用 MV，并提供冲突解决界面；
- 正文：不能在两个完整字符串中二选一，需要 Sequence CRDT。
