## 光标也要 transform

远端操作到达时，本地光标得跟着挪。Stage 1 以来我们是手写朴素规则，其实不用——**把光标看成一个空串 insert，直接复用 transform**：

```js
function transformPos(pos, op) {
  return transform({ kind: 'insert', pos, str: '' }, op, false).pos;
}
```

两个精妙之处：

- 删除区间覆盖光标时，"作废"返回值恰好把光标夹在删除起点——白送的正确行为
- `opIsLeft` 恒为 `false`：同位置并发插入时光标跟随后到文本。**裁决方向两端必须全局一致**，否则你我看到的光标位置错位——和操作的同位置裁决是同一个道理

## 远端光标：分两段修正

光标消息 `{ type:'cursor', pos, baseRev, from }` 不定序、不进 history，但同样会过期：

1. **服务端**：针对 `history[baseRev..rev-1]` 逐个修正再转发
2. **客户端**：收到后若本地还有未确认操作（pending/buffer），再针对它们换算一次——因为本地文档 = 服务端文档 + 未确认操作

demo 里编辑器下方有"文档镜像"：蓝线是我的光标，橙线是对方的，实时跟随。

## 压力测试：收敛性的硬证据

demo 页点「🤖 机器人压力测试」：70ms 间隔随机插入/删除共 80 次，**走和真人输入完全相同的链路**（textarea → input 事件 → diff → 发送）。两个标签页同时跑，等队列清零后对比校验值——必然一致。

> 教学意义：OT 的正确性不是靠"我试了下没坏"，而是随机高压下的**确定性收敛**。
