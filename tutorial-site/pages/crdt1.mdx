# C1 · 最简 CRDT

CRDT 篇回答一个新问题：**没有中心服务器定序，凭什么还能收敛？** 先不碰文本，用两个最简单的数据结构建立直觉。注意：没有服务端了——两个对等节点互发状态快照直接合并。

## 两个数据结构

**G-Counter（只增计数器）**：每个节点只改自己那一格，merge 对每格取 `max`：

```js
{ counts: { A: 2, B: 1 } }   // merge(a, b) → 每格 max
```

**LWW-Register（寄存器）**：逻辑时钟大者胜，并列按写入者 id 字典序裁决：

```js
{ value, n: 逻辑时钟, by: 写入者 }
```

## 核心认知：三条数学性质

CRDT 不靠定序，靠 merge 是纯函数且满足：

| 性质 | 含义 | 抵御的网络问题 |
|---|---|---|
| 交换律 | merge(a,b) = merge(b,a) | 消息乱序 |
| 结合律 | merge(merge(a,b),c) = merge(a,merge(b,c)) | 分批合并、拓扑任意 |
| 幂等 | merge(a,a) = a | 重复投递 |

> **设计要点**：状态里不放「我是谁」。节点身份属于副本，不属于 CRDT 状态——否则 merge 结果依赖操作数顺序，交换律在对象层面就不严格成立（自动化测试真抓到过这个问题）。

## 小结

**✅ 学会了什么**：merge 三性质；状态型同步 = 快照 + 纯函数合并；身份不属于状态。

**⚠️ 还有什么问题**：计数器只能增；寄存器并发写**会丢一个**（last-writer-wins）。
