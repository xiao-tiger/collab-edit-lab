# C1 · 两条评论为什么只剩一条

小明和小红同时编辑一份在线文档。两个人都暂时断网，各自新增了一条评论：

```text
开始：评论数 0
小明：0 + 1 = 1
小红：0 + 1 = 1
```

重连后，如果双方只是把自己的 `count = 1` 发给对方，最终仍然只有一条评论。系统虽然“同步成功”，却悄悄丢了一次修改。

## 问题出在哪里

一个可以被任何人覆盖的总数，不知道这个 `1` 是谁增加的。CRDT 的第一步不是更聪明地传消息，而是**改变数据结构**：每个副本只修改属于自己的一格。

## 动手解决

先用默认的“CRDT merge”完整走一遍，再切换到“朴素覆盖”。打开“反转管道顺序”和“重复最后一包”，观察正确算法为什么不受影响。

## 本章答案

计数状态从一个数字变成：

```js
{ A: 1, B: 1 }
```

合并时每格取 `max`，读取时再求和。这个 `merge` 具备三条重要性质：

- 交换律：先收到 A 还是 B，结果相同；
- 结合律：分几批合并，结果相同；
- 幂等性：同一条消息收到多次，不会重复计数。

注意：**不是所有 CRDT 都取 max。** `max` 只是这个计数器的合并方法；其他数据结构会有自己的 `merge`。

## 留给下一章的问题

计数器可以把修改拆到不同格子，但文档标题只有一个值：

```text
A：把“周报”改成“周报 v2”
B：把“周报”改成“周报最终版”
```

B 是看过 A 的修改后再改，还是两个人互不知情地同时改？下一章用版本向量判断这两种完全不同的关系。
