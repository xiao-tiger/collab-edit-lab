# Stage 3 · 过期坐标怎样被修正

B 的 `delete(3,1)` 基于旧文档，服务端已经先接受了 A 在开头插入的两个字。B 真正想删除的“报”从位置 3 移到了位置 5。

`transform` 的任务不是决定谁输谁赢，而是回答：

> `other` 已经应用后，怎样修改 `op` 的坐标，才能继续表达原来的意图？

## 四组基础规则

| 我的操作 | 已经应用的 other | 处理方向 |
|---|---|---|
| insert | insert | other 在左侧则右移；同位置按统一顺序裁决 |
| insert | delete | 左侧删除则左移；插入点被删除覆盖时作废 |
| delete | insert | 左侧插入则右移；插入落入删除区间时被吸收 |
| delete | delete | 去掉双方重叠部分，只删除剩余区间 |

核心收敛条件是：

```js
applyOp(applyOp(doc, a), transform(b, a))
===
applyOp(applyOp(doc, b), transform(a, b))
```

## 本章答案

服务端针对 `history.slice(baseRev)` 逐个 transform 过期操作，再把修正后的操作当作正常操作接受。用户的坐标可能改变，修改意图仍然保留。
