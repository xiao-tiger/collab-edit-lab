# Stage 0 · 全量文本广播

每敲一个字，把整篇文档发给所有人 —— 后到者胜（last-write-wins）。最直觉，也最容易出事的办法。

## 动手实验

<OtPlayground policy="fulltext" latency={600}>
在两个框里**同时**快速打字 → 观察内容互相覆盖、服务端区域显示「已发散 ❌」
</OtPlayground>

## 为什么会出问题

假设文档是 `"abc"`，同一瞬间：

```
A 在末尾敲 X → 发出全量 "abcX"
B 在开头敲 Y → 发出全量 "Yabc"

正确结果应是 "YabcX"，但两条全量文本互相覆盖：
  A 收到 "Yabc" → 自己的 X 被抹掉
  B 收到 "abcX" → 自己的 Y 被抹掉
```

关键代码就三行，问题也在这三行里：

```js
// 客户端：每次输入，把整篇文档发出去
editor.addEventListener('input', () => {
  ws.send(JSON.stringify({ type: 'update', text: editor.value }));
});

// 服务端：全量覆盖，广播给其他人
doc = msg.text;
broadcast({ type: 'update', text: doc });
```

> **根因**：全量文本不携带「意图」。「在位置 3 插入 X」可以合并，「整篇变成 abcX」只能互相覆盖。另外收到更新直接覆盖 `textarea.value`，光标还会被拍飞。

## 小结

**✅ 学会了什么**：协同 = 多端副本要收敛；last-write-wins 在并发下必然丢数据。

**⚠️ 还有什么问题**：并发互相覆盖、丢字；发散后双方毫无察觉；服务端不知道你改了哪。

**→ 下一阶段**：不传全文，传「操作」—— insert / delete。
