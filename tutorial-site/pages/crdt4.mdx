# C4 · 上手 Yjs（工业级 CRDT）

用工业级库搭真协同编辑器。你会发现 Yjs 的每个概念，都有我们手写过的对应物——这就是先造轮子的回报。

## 动手实验

Yjs 需要真实服务端（虽然它只是个哑管道），在可运行 demo 里玩：

```bash
npm run crdt:4   # → http://localhost:8014，开两个标签页
```

实验：① 同时打字 → 收敛（没有任何"回执/修正"——CRDT 不需要）② **停掉服务端**继续打字 → 刷新页面内容还在（IndexedDB）→ 重启服务端 → 自动合并 ③ DevTools 看 WS 帧：二进制编码 + 增量同步

## 概念映射表（手写的 → 工业的）

| 我们手写的 | Yjs 里的对应 | 说明 |
|---|---|---|
| RGA items + Map（C2） | `Y.Doc` + `Y.Text` | 内部是 YATA 算法：解决 RGA 交错问题，自动合并相邻 Item 控制体积 |
| 全量快照互换（C2/C3） | sync step | 增量同步：状态向量只交换缺失的更新 |
| Stage 4 的光标同步 | `provider.awareness` | 临时状态（光标/选区/在线名单）专用通道，不落文档 |
| Stage 5 的 data.json | `IndexeddbPersistence` | 浏览器本地持久化：刷新、断网重开都在 |
| OT 的中心定序服务端 | y-websocket 服务端 | **哑管道**：不定序、不变换、不理解内容 |

## 代码结构（~60 行）

- `server.js`：静态服务 + `setupWSConnection`（房间 = WS 路径）
- `client.js`：`Y.Doc` ↔ textarea 双向绑定（diff + `ydoc.transact`）+ Awareness 在线名单 + IndexedDB

## 继续深入
