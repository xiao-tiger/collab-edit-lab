# CRDT Stage C2：迷你 RGA —— 文本 CRDT

> 前置：C1（merge 三性质）。本阶段把 CRDT 用到文本上——这是整个 CRDT 篇的核心，约 80 行核心代码。

## 运行

```bash
npm run crdt:2   # 或 open crdt/02-rga/index.html
```

## 文件结构（三层分离，按此顺序读）

| 文件 | 层 | 职责 |
|---|---|---|
| `rga.js` | 算法层 | RGA：Item、插入/删除、并集合并、序列重建（canonical 版本） |
| `sim.js` | 数据层 | 双节点 + 虚拟网络 + diff 翻译 + 同步流程，无 DOM |
| `app.js` | 渲染层 | textarea 绑定、Item 结构（墓碑）渲染 |
| `index.html` | 结构 | 页面骨架与样式 |

## 核心思想：给每个字符发"身份证"

OT 用**相对位置**（pos）定位字符，所以并发下坐标会过期，需要服务端定序 + transform。RGA 换一个世界观：**每个字符一个全局唯一的身份**：

```js
Item = {
  id: 'B:3',        // 站点id + 计数器，全局唯一、可比较
  left: 'A:5',      // 我插入时左边那个字符的 id（"我出生在谁右边"）
  ch: 'X',
  deleted: false,   // 删除 = 打墓碑，不物理移除（否则后来者无法引用它）
}
```

- **插入**：新字符的 `left` 指向目标位置左边的字符
- **删除**：打墓碑标记
- **合并**：按 id 求并集（墓碑"删过即删"）——交换/结合/幂等由并集天然保证
- **重建文本**：从根 DFS；同一 `left` 的并发兄弟按 id **降序**（"后来者居左"）。为什么必须降序：若在开头打字时新字符排到已有字符后面，用户在一处打字、字却出现在另一处——UX 错误。降序让新字符落回输入位置，且全局一致、收敛性不变（我们的测试真抓到过这个问题）

## 与 OT 的对照（重要！）

| | OT（stage3） | RGA（C2） |
|---|---|---|
| 定位 | 相对位置 pos | 绝对身份 id |
| 并发修正 | transform + 中心定序 | 不需要——不存在"过期" |
| 版本号 | rev / baseRev 必需 | 不需要 |
| delete × 并发 insert | **吸收**（插入被删） | **插入存活**（墓碑不影响兄弟） |
| 乱序/重复 | 需要定序保证 | 天然免疫 |
| 代价 | 需要中心服务器 | 墓碑膨胀、每字符元数据 |

## 实验

1. 两边同时打字 → 文本与**内部结构**都收敛（页面下方把每个 Item 的 id 画出来了，删除线是墓碑）
2. 勾"重复投递"/"乱序" → 毫无影响（状态并集免疫）
3. A 删一段的同时 B 往这段里打字 → B 的字**存活**（对照 OT 规则三的吸收）
4. 观察墓碑：删掉的字符从未离开结构 → 想想一年后的文档有多大？（→ Yjs 的 GC/压缩，C4 提）

## 已知局限

1. **交错问题**：两站点交替并发插入同一位置，可能把两段文字交错（Yjs 的 YATA 算法解决）
2. 墓碑只增不减
3. 状态型每次发全量 Item 集合；生产用操作型（CmRDT）+ 因果广播
