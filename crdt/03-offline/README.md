# CRDT Stage C3：离线合并实测

> 前置：C2（RGA）。本阶段不引入新数据结构，只做一件事：**亲手验证 CRDT 的杀手级场景——离线编辑**。

## 运行

```bash
npm run crdt:3   # 或 open crdt/03-offline/index.html
```

## 文件结构（三层分离）

| 文件 | 层 | 职责 |
|---|---|---|
| `rga.js` | 算法层 | RGA（教学副本，canonical 在 `crdt/02-rga/`） |
| `net.js` | 网络层 | 虚拟网络（教学副本） |
| `sim.js` | 数据层 | 与 C2 副本一致，含断网/重连逻辑（`setOnline(false)` 时 send 失败只记 dirty） |
| `app.js` | 渲染层 | 断网按钮、未同步标记、文本同步 |
| `index.html` | 结构 | 页面骨架与样式 |

## 实验

1. 点「⚡ 断开网络」→ 两端消息通道关闭
2. A、B 各自随便打字、删改（文本自由分叉，页面琥珀色提示"已分叉"）
3. 点「🔌 重新连接」→ 两端互换**一次最终状态**→ 瞬间收敛 ✅

## 核心认知：状态型 CRDT 的离线为何如此便宜

| | OT（stage 系列） | 状态型 CRDT |
|---|---|---|
| 离线期间 | 要缓存全部操作，且重连后 baseRev 早已过期，需要服务端变换一长串历史；超出快照还要全量重同步 | 什么都不用做，最终状态本身就在本地 |
| 重连合并 | 依赖服务端权威定序 | 互换一次快照，并集即收敛 |
| 断网几天 | 基本不可行 | 天然支持 |

这就是为什么离线优先产品（以及 P2P、端到端加密场景）选 CRDT：**收敛不依赖任何在线权威**。

## 对照 OT 篇 Stage 5

OT 篇的快照/resync 机制本质是"放弃合并、回到权威"；CRDT 的快照（状态）本身就是可合并单元。同样叫"快照"，世界观完全不同。

## 已知简化

- 每次同步发全量 Item 集合（教学清晰）；生产用操作型 CRDT + 版本向量做增量同步（Yjs 的 sync step 就是这么做的，C4 可以观察到）
- 未演示"断网时删除对方离线新增内容"等更深交互——合并规则同样覆盖
