# CRDT Stage C1：最简 CRDT —— G-Counter 与 LWW-Register（真服务端版）

> 前置：OT 篇（stage0~5）。CRDT 篇回答一个新问题：**没有中心定序，凭什么还能收敛？**
> 本阶段用两个最简单的数据结构建立直觉。

## 运行

```bash
npm run crdt:1   # 或 node crdt/01-counter-register/server.js → http://localhost:8011
```

**每个浏览器标签页 = 一个节点**（随机分配节点 id），多开几个标签页互玩。

## 架构：服务端有多"哑"

```
标签页 A（节点）            服务端（中转 + 存档）            标签页 B（节点）
 本地 CRDT 状态                一份 merge 存档                 本地 CRDT 状态
     │ +1 → 发快照 {from, counter, reg}        │
     │ ─────────── ws ───────────→  ① merge 进存档（纯函数）
     │                               ② 原样转发给其他节点
     │              ws ←────────────  收到快照 → merge → 一致 ✅
```

对比 OT 篇：那里的服务端是**权威**（定序 + transform）；这里的服务端**不定序、不裁决、不理解业务**，只做搬运和存档——收敛完全靠客户端的 CRDT merge。存档副本的唯一作用是让新加入的标签页追上进度。

## 协议（就两种消息）

| 方向 | 消息 | 说明 |
|---|---|---|
| 客户端 → 服务端 | `{type:'snapshot', from, counter, reg}` | 每次本地变更后发送**最终状态** |
| 服务端 → 客户端 | `{type:'init', ...}`（连上时）/ `{type:'snapshot', ...}`（中转） | 对方 merge 即可 |

## 文件结构（三层分离，按此顺序读）

| 文件 | 层 | 职责 |
|---|---|---|
| `server.js` | 服务端 | 静态服务 + 中转 + 存档副本（~60 行） |
| `public/crdt-core.js` | 算法层 | G-Counter / LWW-Register 的状态与 merge（ESM，浏览器与 Node 通用；canonical 版本） |
| `public/client.js` | 数据层 | 本节点状态 + ws 收发（五段直线结构：状态→操作→发送→接收→快照） |
| `public/app.js` | 渲染层 | 画快照、转发用户操作 |
| `public/index.html` | 结构 | 页面骨架与样式 |

## 本阶段实现

### G-Counter（只增计数器）

```
状态：{ counts: { A: 2, B: 1 } }   ← 每个节点只改自己那一格
merge：对每一格取 max
```

### LWW-Register（最后写入者胜寄存器）

```
状态：{ value, n: 逻辑时钟, by: 写入者 }
merge：n 大者胜；n 并列按 by 字典序裁决
```

永不发散，但**并发写会丢一个**（last-writer-wins）——C2 的动机。

### 设计要点：状态里不放"我是谁"

节点身份属于副本（replica），不属于 CRDT 状态。否则 merge 结果依赖操作数顺序，交换律不严格成立。

## 核心认知：三条数学性质

| 性质 | 含义 | 抵御的网络问题 |
|---|---|---|
| 交换律 | merge(a,b) = merge(b,a) | 消息乱序 |
| 结合律 | merge(merge(a,b),c) = merge(a,merge(b,c)) | 分批合并、拓扑任意 |
| 幂等 | merge(a,a) = a | 重复投递 |

## 实验

1. **基本同步**：两个标签页点 +1、写寄存器 → 两边 counts 集合一致
2. **勾"随机延迟（乱序）"** → 快照乱跳照样收敛（交换律）
3. **勾"重复发送"** → 同一份快照送两次，计数不多算（幂等）
4. **存档副本**：先在一个标签页点若干次，再开新标签页 → 新节点通过 init 追上进度
5. 观察服务端日志：`[中转]` 行能看到它只做 merge+转发，从不裁决

## 已知局限

- 计数器只能增（要减需要 PN-Counter：两个 G-Counter 一增一减）
- 寄存器并发写会丢（LWW 取舍）
- 文本需要"每个字符都可合并"——**C2 的 RGA**
